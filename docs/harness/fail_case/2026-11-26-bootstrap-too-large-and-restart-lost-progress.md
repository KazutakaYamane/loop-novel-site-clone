# 2026-11-26 bootstrap が大きすぎ、起動し直しで進み具合を失いかけた

## 前提

- bootstrap(Issue #1)は、1つのエージェントが1つのセッションで、次のすべてを作る作りだった。
  - テストの道具(Pest、Larastan、Infection、Vitest、Stryker、Playwright)
  - worktree ごとの環境を作るスクリプト
  - CI の7つのジョブ(`backend` `frontend` `e2e` `mutation` `visual` `ac-coverage` `guard`)
  - metrics のワークフロー、PR のひな形、CODEOWNERS、文書
- 予算は bootstrap 全体で 80 USD 相当(`MAX_COST_USD_BOOTSTRAP`)。カナリアが一致するまで最大4回やり直す。
- 作ったあとは、別のエージェントがカナリアの PR を約40本出し、CI がそれぞれを期待どおりに止めるか確かめる。
- サブスクリプションの利用上限(5時間枠)に当たると、まとめ役が上限の明ける時刻まで待ち、同じセッションを `--resume` で続ける。ただし、まとめ役のプロセスが生きている間に限る。
- まとめ役(`scripts/loop/run.sh bootstrap`)は、ループの設計と調整に使っていた Claude Code のセッションの中で、バックグラウンドタスクとして起動していた。

## 起きたこと

1. **1つのセッションに対してタスクが大きすぎた。** 予算の上限や利用上限に当たる前に終わる見込みが立たなかった。予算を超えると、待っても直らないので人間の判断待ちになる。
2. **まとめ役が Claude Code のセッションにつながっていた。** そのセッションを閉じるとまとめ役も止まるので、数時間かかる bootstrap には向かなかった。
3. **進み具合を確かめずに止めて、起動し直した。** 設計役は「まだカナリアの仕様を作っている段階だから、止めても失うものは少ない」と判断した。古い情報をもとにした判断で、実際にはもっと先まで進んでいた。
   - bootstrap の round 1 は終わっていた(PR #2)
   - カナリアの PR 43本(#3〜#45)が出され、判定も終わっていた
   - 判定は不合格だった(12ケース)。例: 正しい変更の対照ケースが mutation で赤になった。弱いテストのケースを mutation が止めなかった。ずるの検出(guard)が見逃したケースがあった
4. **止めたときに、カナリアの PR を閉じる途中だった。** #3〜#15 の13本が開いたまま残った。
5. **起動し直すと、やり直しの回数が1に戻り、不合格の内容も引き継がれなかった。** 新しいエージェントは不合格を知らないまま、作業をやり直し始めていた。
6. (小さな問題)プロセスグループを指定して止めようとしたが失敗した。番号の取り違えが原因で、プロセスを直接指定して止め直した。

## 修正

| 問題 | 修正 |
|---|---|
| タスクが大きすぎる | bootstrap を `tooling` → `ci-checks` → `ci-guard` → `finish` の段階に分けた。段階ごとに別のセッションと予算(`MAX_COST_USD_BOOTSTRAP_STAGE`=30)を割り当て、同じブランチと PR に積み上げる |
| 不合格の直しが大きい | 不合格のケースを担当ごとに分ける(`canaries.py split-feedback`)。CI1〜4 と、guard 以外で落ちた対照ケースは `fix-checks`、CI5・CI6・ずるの検出・保護パス・依存の許可リストは `fix-guard` に回し、担当ごとに別のセッションで直す |
| 起動し直すと進み具合を失う | 終わった段階を `../loop-novel-site-clone.loop/bootstrap-stages.done` に、終わった直しを `canaries/round-N/fix-*.done` に記録する。起動し直すと、それらを飛ばし、最後にカナリアを試した round の次から、その不合格を引き継いで続ける。判定役は round ごとに1回だけ動かす(`arbitrated` の印で判断する) |
| 中断した作業をやり直してしまう | bootstrap の指示文に「ブランチに前回の作業が残っていれば、正しい部分を残して続きから進める」を足した |
| Claude Code につながっている | `setsid nohup` で切り離して起動する。設計役のセッションを閉じても止まらない(PC のスリープや再起動では止まる) |
| カナリアの PR が残った | 残った #3〜#15 を閉じた。起動し直したときにも `canaries.py close` で残りを閉じる |

## 教訓

- 止める前に、ログ(`bootstrap-run.log`、`canaries/`)と GitHub の PR を見て、いまどこまで進んでいるかを確かめる。記憶や古い情報で判断しない。
- 長く動く処理は、最初から設計役のセッションと切り離して起動する。
- 何時間もかかる処理は、途中で止まっても続きから再開できるように、段階ごとの完了を記録する作りにする。
- 1つのセッションの仕事は、予算と利用上限の範囲で終わる大きさに分ける。
