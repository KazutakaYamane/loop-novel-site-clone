# 要件書(マイルストーン2まで)

## 0. この文書の位置づけ

- 小説投稿サイト「カクヨム」のクローンについて、**何を作るか**だけを書く。どう作るか(画面の構成、データモデル、API、認証方式、キャッシュの方式、層の分け方など)は書かない。それらは実装する側が決め、決めた理由を `docs/adr/` に1件ずつ残す。
- 各要件の受け入れ条件には `AC-<機能>-<番号>` の ID を付ける。Issue に分けるときは、その Issue が満たす AC の ID を書く。各 AC は、その ID をタグに付けた E2E テストで確かめる。
- 受け入れ条件に書いていないことは、実装する側の判断に任せる。判断に迷う、または受け入れ条件どうしが矛盾する場合は、推測で埋めずにエスカレーションする。

## 1. ゴール

マイルストーン2の完了は次の状態とする。

- ゲストがトップから作品ページ、話ページへ進み、シードの作品を読める。
- 1つのボタンでデモ作者になり、作品を作って話を書き、公開すると、ゲストが見る作品ページ・話ページ・トップの新着に即時に出る。
- 本文のルビ・傍点の記法が、カクヨムと同じ規則で表示される。
- 毎日決まった時刻に、すべてのデータがシードの状態に戻る。
- 話ページの性能を計測した結果が残っている。

## 2. 固定する前提

| 項目 | 内容 |
|---|---|
| バックエンド | Laravel(PHP)。API を提供する |
| フロントエンド | Next.js(TypeScript)。画面はすべて Next.js が描画する |
| データベース | MySQL |
| 実行環境 | ローカルの Docker Compose で完結させる。本番環境、インフラのコード、デプロイは範囲外 |
| README | 実装する側が書き、変更に合わせて更新する。後で人間が書き直すことがある |

上の表にないミドルウェア(キャッシュ、キューなど)を使うかどうかは、実装する側が決める。

## 3. 利用者

| 利用者 | 目的 | 典型的な行動 |
|---|---|---|
| 作者 | 書いたものを読んでもらう | 作品を作り、話を書いて公開する |
| 読者 | 面白い作品を見つけて読む | トップから作品を選び、話を読む |
| 評価者 | このクローンが本番品質で作られているかを判断する | 短い時間でデモを触り、コードを数ファイル読む |

- 作者と読者は同じアカウントで、役割は「その作品の所有者かどうか」で決まる(カクヨムと同じ)。
- 評価者はカクヨムの仕様を細部まで知っている。会員登録を求められると、触らずに離脱する。表示が遅い、データが空、落ちている、のどれかで評価が大きく下がる。

## 4. 機能要件

### F1 ログアウトとログイン状態

このサイトは個人情報を保持しない。会員登録とメールアドレス・パスワードでのログインの入口(画面・API)は閉じ、利用者にメールアドレスやパスワードを入力させない。処理そのものは F2 のデモログインが内部で使う。ログイン画面は残し、その理由とデモログイン(F2)のボタンを出す。利用者を作る方法はデモログインだけにする。

- AC-F1-1: ログアウトすると、ログインが必要な画面を開けなくなる。
- AC-F1-2: ログインしていない状態でログインが必要な画面を開くと、ログイン画面へ案内される。
- AC-F1-3: ログイン状態を表す情報は、ブラウザの JavaScript から読めない。
- AC-F1-4: 他のサイトから、ログイン中の利用者になりすまして更新の操作を送れない(CSRF)。
- AC-F1-5: ログイン画面に、個人情報を保持しないため会員登録とログインを無効にしている旨と、F2 のデモのボタンが表示される。メールアドレス・パスワードの入力欄は無い。デモのボタンを押すと、F2 と同じくログインした状態になる。
- AC-F1-6: ヘッダー(未ログイン)の「ログイン」から、ログイン画面へ移動できる。会員登録の画面は無い。

### F2 デモログイン

評価者がアカウントを作らずに、作者・読者として触れるようにする。

- AC-F2-1: トップとヘッダーに「デモ作者として始める」「デモ読者として始める」の2つのボタンがある。
- AC-F2-2: ボタンを押すと新しいユーザーが作られ、そのままログインした状態になる。会員登録とメールアドレス・パスワードでのログインの処理は、通常のサイトと同じものとして実装し、デモのボタンはそれを内部で使う(予約ドメインのアドレスと、利用者に見せないパスワードでユーザーを作り、そのアカウントでログインする)。会員登録とログインの処理には、利用者が画面や API から直接呼べる経路を持たない。デモ専用の権限・表示・認証の経路は持たない。
- AC-F2-3: デモのユーザーの名前は、一覧で互いに区別できるものにする。
- AC-F2-4: 同じユーザーに戻る手段は持たない。ログアウトした後やログイン状態が切れた後にもう一度ボタンを押すと、新しいユーザーになる。
- AC-F2-5: デモ作者は、下書きの話と公開済みの話を持つ作品を1つ持った状態で始まり、執筆の画面へ移動する。
- AC-F2-6: デモ読者は、何も持たない状態で始まり、トップへ移動する。
- AC-F2-7: デモログインは、IP アドレス単位で1時間に10回までに制限される。超えると、その旨が表示される。
- AC-F2-8: ユーザーの情報に、個人を特定する情報を含めない。デモのユーザーのメールアドレスは、実在のアドレスと衝突せずメールも届かないドメイン(RFC 2606 の予約ドメイン)にする。パスワードは利用者に見せず、どこにも残さない。

### F3 作品の作成・編集

- AC-F3-1: ログインした利用者は、タイトルとあらすじを入力して作品を作れる。
- AC-F3-2: 作品には次の項目を設定・変更できる: タイトル、キャッチコピー、あらすじ(画面での名前は「紹介文」)、ジャンル(1つ)、タグ(複数)、セルフレイティング(残酷描写・暴力描写・性描写のそれぞれ有無)、連載状態(連載中・完結)。
- AC-F3-3: ジャンルの選択肢、各項目の文字数の上限、タグの数の上限は、カクヨムに合わせる。カクヨムで確かめられない値は、実装する側が決めて ADR に書く。
- AC-F3-4: 作品を編集できるのは、その作品の所有者だけである。他の利用者が編集しようとすると拒否される。
- AC-F3-5: 公開済みの話が1つもない作品は、ゲストから見えない。

作品の削除は作らない。

### F4 話の下書き・公開

- AC-F4-1: 作品の所有者は、話のタイトルと本文(プレーンテキスト)を入力し、下書きとして保存できる。
- AC-F4-2: 下書きの話は、何度でも編集して保存し直せる。
- AC-F4-3: 下書きの話は、所有者以外には見えない(ゲスト・他の利用者が話ページを開くと「見つからない」になる)。
- AC-F4-4: 所有者が下書きの話を公開すると、その直後にゲストが開いた作品ページ・話ページ・トップの新着に、その話が出る。
- AC-F4-5: 作品の中で初めて話を公開すると、作品もゲストから見えるようになる。
- AC-F4-6: 本文が空の話は公開できず、その旨が表示される。
- AC-F4-7: 所有者以外は、話を作成・編集・公開できない。
- AC-F4-8: 話は作成した順に並ぶ。
- AC-F4-9: 話の作成・編集の送信回数は、利用者単位で制限される。

予約公開、公開後の編集、非公開に戻す操作、話の並び替え、話の削除は作らない。

### F5 ルビ・傍点の記法

本文の記法を、カクヨムのヘルプ(https://kakuyomu.jp/help/entry/notation)と実際の表示に合わせて変換する。下の規則は、ヘルプと、カクヨムの実画面で確かめた挙動をまとめたものである。

- AC-F5-1(自動ルビ): `漢字《かんじ》` は、`《` の直前に連続する漢字だけを親文字にする。`今日は東京《とうきょう》へ` では「東京」だけにルビが付く。
- AC-F5-2(漢字の判定): Unicode の漢字に加えて、`々`・`〆`・`ヶ`・`〇` を漢字として扱う。`佐々木《ささき》` は全体が親文字になる。
- AC-F5-3(親文字がない): `《` の直前が漢字でなければルビにしない。`ひらがな《ルビ》` は記法の文字のまま表示する。
- AC-F5-4(明示ルビ): `|` または `｜` の後ろから `《` までを親文字にする。漢字以外も親文字にできる(`｜ロンドン《倫敦》`)。
- AC-F5-5(縦線の扱い): 親文字の指定に使った縦線は表示しない。ルビにならなかった縦線は文字として表示する。縦線は直後の `《…》` にだけ効き、その `《…》` がルビにならなくても、次の `《` には持ち越さない(`｜あ《》い《う》` は全体が文字のまま)。
- AC-F5-6(上限): ルビは50文字まで、親文字は20文字まで(コードポイント単位)。ルビが50文字を超えたらルビにせず、記法の文字のまま表示する。
- AC-F5-7(自動ルビの親文字が長い): `《` の直前の漢字が20文字を超えるときは、`《` に近い側の20文字を親文字にする。
- AC-F5-8(明示ルビの親文字が長い): 縦線から `《` までが20文字を超えるときは、縦線を文字として残し、自動ルビとして扱う。`｜` + 漢字21文字 + `《るび》` は、縦線と1文字目が文字になり、残りの20文字にルビが付く。親文字に漢字がなければ、記法の文字のまま表示する。
- AC-F5-9(`《` のエスケープ): `｜《`(`|《` も)は `《` という文字になり、縦線は表示しない。`｜《《傍点》》` は `《《傍点》》` という文字になる。
- AC-F5-10(傍点): `《《傍点》》` は、中身に傍点を付けて表示する。中身の長さに上限はない。中身が空(`《《》》`)なら記法の文字のまま表示する。
- AC-F5-11(閉じていない記法): `《` に対応する `》` が同じ行にない場合は、記法の文字のまま表示する。記法は改行をまたがない。
- AC-F5-12(入れ子): ルビになった `《…》` の中の記法は解釈しない。傍点の中のルビも解釈せず、傍点の中身は文字のまま表示する。
- AC-F5-13(ルビが空): `漢字《》` はルビにせず、記法の文字のまま表示する。
- AC-F5-14(異体字セレクタ): 異体字セレクタ(SVS・IVS)は漢字として扱わず、自動ルビの漢字の連続はそこで切れる。`葛󠄀城《かつらぎ》`(IVS 付き)は「城」だけにルビが付く。
- AC-F5-15(サロゲートペア): `𠮟` など、サロゲートペアの漢字も1文字の漢字として扱う。
- AC-F5-16(XSS): 本文に `<script>` などの HTML を書いても、文字として表示され、実行されない。
- AC-F5-17(性能): 閉じない `《` や `《《` を大量に含む行(例: `《` を10万個並べた行)でも、1秒以内に表示できる。

### F6 作品ページ・話ページ

- AC-F6-1: 作品ページに、作品の情報(F3 の項目と作者名)と、公開済みの話の目次が表示される。
- AC-F6-2: 話ページに、作品名、話のタイトル、本文が表示され、前の話・次の話・目次へ移動できる。最初の話に「前の話」、最後の話に「次の話」は出さない。
- AC-F6-3: 作品ページ・話ページに OGP(タイトル、説明)が設定されている。
- AC-F6-4: 存在しない、または公開されていない作品・話のページは「見つからない」になる。
- AC-F6-5: 本文の段落・空行は、入力したとおりに表示される。

### F7 トップページ

- AC-F7-1: トップに、話が公開された時刻が新しい順に作品が並ぶ(新着の更新作品)。
- AC-F7-2: 作品を選ぶと作品ページへ移動する。
- AC-F7-3: マイルストーン2では、ランキング・検索・ジャンル一覧への導線を出さない。

### F8 シードデータ

- AC-F8-1: 青空文庫の著作権が切れた作品を、複数のジャンルに分けて10〜20作品入れる。各作品の作者は、シードのユーザーとして作られる。
- AC-F8-2: 各作品のクレジット(底本・入力者・校正者など、青空文庫が表示を求める情報)が、作品の中で読める。
- AC-F8-3: 青空文庫のルビは、F5 の記法として表示される。青空文庫の注記(`［＃…］`)は画面に出ない。
- AC-F8-4: 作品のキャッチコピーとあらすじは、作品を読んで新たに書く(既存の解説文を写さない)。
- AC-F8-5: シードの投入とリセットは、ネットワークに接続せずに行える(青空文庫からの取得は開発時に行い、結果をリポジトリに入れる)。
- AC-F8-6: シードの作品は、トップの新着にもその順で並ぶよう、公開時刻を持つ。

### F9 日次リセット

公開しているデモのデータを残す必要がないため、毎日すべてのデータをシードの状態に戻す。デモのユーザーの後片付けと、荒らしへの対処を兼ねる。

- AC-F9-1: 毎日 4:00(日本時間)に、すべてのデータ(デモのユーザー、ログイン状態、作品、話、キャッシュなどの一時的なデータを含む)がシードの状態に戻る。
- AC-F9-2: リセットは、決まった時刻を待たずに、1つのコマンドでも実行できる。
- AC-F9-3: リセットの直後、トップ・作品ページ・話ページにシードの作品が表示され、リセット前に公開された話はどこにも表示されない。
- AC-F9-4: リセット前にログインしていた利用者が操作すると、「デモを始め直す」案内が表示され、ログイン状態は解除される。

## 5. 見た目

- すべての画面の見た目を、PC とスマートフォンの両方の幅でカクヨムに合わせる。最も厚く合わせるのは話ページとする。画面の文言もカクヨムに合わせる。
- 合わせるための参照(スクリーンショット、寸法、色などの値)は、実装する側がカクヨムの画面から採取し、リポジトリに残す。採取の手順と禁止事項は `docs/kakuyomu-reference.md` に従う(カクヨムに負荷や変化を与えない、投稿された作品の内容を取得しない)。
- カクヨムの CSS・画像・フォントはコピーせず、採取した値から書く。
- ロゴとバナーは同じ寸法のダミーにし、サイト名を「カクヨム」にしない。
- すべてのページに `noindex` を付け、フッターに非公式のクローンである旨を表示する。

## 6. 非機能要件

| 項目 | 要件 |
|---|---|
| 性能 | k6 で話ページの p95 とスループットをローカルで計測し、計測の条件と結果を `docs/performance.md` に残す。表示を速くするために行った工夫と、その効果がわかる比較を含める |
| 認可 | 作品・話の更新は所有者だけに許す(AC-F3-4、AC-F4-7) |
| 個人情報 | 利用者の個人情報を保持しない(F1、AC-F2-2) |
| レート制限 | デモログインと投稿に制限をかける(AC-F2-7、AC-F4-9) |
| 運用 | アプリのログは構造化(JSON)して出力する |
| テスト・静的解析 | CI の検査(`AGENTS.md` の「Done means CI is green」)をすべて通す |

## 7. 範囲外

マイルストーン3以降で扱うため、作らない。

- 予約公開、公開後の編集、非公開に戻す操作
- 応援(♥)、★評価、ランキング、作者のダッシュボード、PV の集計
- 検索、ジャンル別の一覧、作品フォロー、しおり、応援コメント
- 作品・話の削除、話の並び替え、会員情報の変更・退会
- 本番環境、インフラのコード、デプロイ
- 通報・モデレーション・管理画面

マイルストーンにかかわらず作らない: 会員登録、メールアドレスとパスワードでのログイン、メール認証、パスワードリセット、ソーシャルログイン(F1。ログイン画面は理由の案内とデモのボタンのために残す)。
