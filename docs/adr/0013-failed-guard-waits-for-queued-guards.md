# 0013 落ちた guard は遅れて始まる guard を長く待ち、最後に失敗を足す

- 状態: 採用(0012 の待ち時間と結果の残し方を変える)
- 日付: 2026-11-27

## 背景

0012 では、落ちた guard が他のワークフローの `guard` の終わりを最長 300 秒待ってから、成功した `guard` を失敗に書き換える。PR が多く同時に走ると(カナリアなど)、ジョブはランナーの空きを何十分も待つことがある。書き換えられた guard が 300 秒より後に始まると、落ちた guard はもう終わっていて、書き換えた guard の成功が最新の `guard` として残る。Actions のジョブが作ったチェックをジョブのトークンで書き換えられない場合も、成功が最新として残りうる。

## 決定

- `guard_checks.py` の待ち時間の既定を 40 分にし、3 つの guard ジョブの `timeout-minutes` を 50 にする。待つのは判定が落ちた guard だけなので、違反の無い PR の guard は今までどおりすぐ終わる。
- 待った後、成功した `guard` があれば、それを failure に書き換えたうえで、失敗の `guard` をもう 1 つ足す。書き換えを断られても、成功した guard より後に終わった `guard` が失敗として残る。
- `.github/scripts/tests/test_workflows.py` が、各 guard の `timeout-minutes` が待ち時間より 10 分以上長いことを確かめる。

## 結果

- 書き換えた guard がランナー待ちで遅れても、40 分以内に終われば `guard` は落ちる。まとめ役は全チェックの終わりを待つので、落ちた guard が待っている間に結果が決まることはない。
- 違反を見つけた PR のうち、成功した `guard` があるもの(guard を書き換えた PR)だけ、失敗のチェックが 1 つ増える。
