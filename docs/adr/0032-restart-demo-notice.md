# 0032 期限切れのログインにデモの再開を案内する

- 状態: 採用
- 日付: 2026-11-28

## 背景

#131 はリセットでログイン状態を失ったブラウザーを個別に案内する(AC-F9-4)。以前にログインしたことを表す暗号化 cookie の扱いは ADR 0015 で決めた。`docs/kakuyomu-reference/session-notice.md` では、期限切れに固有の文言は採取できなかった。

## 決定

- ログインの処理が既定のセッションの寿命より 24 時間長い `yomikaki_previous_login` を付け、ログアウトの処理が消す。値は利用者に依存しない。暗号化・HttpOnly・SameSite=Lax を使う。
- Laravel は既存のユーザー・CSRF トークン取得経路や認証エラーで、有効なログインが無く暗号化 cookie が残っているときだけ `X-Demo-Session-Expired: 1` を付ける。認証・CSRF の可否や HTTP ステータスは既存のルールどおり。
- 初回のページ表示では Next.js のサーバーがユーザー取得の応答を読んで案内を描く。クライアント側のページ移動ではログイン中の画面が期限切れを調べて描画を更新する。開いたままのフォームが送信時に期限切れを検出した場合はログイン画面へ移動する。デモを始める操作はゲスト用の CSRF トークンで続けられる。
- 採取したゲスト向けの帯に合わせ、見出し「ログイン状態が解除されました」、説明「ヨミカキを使うには、新しいデモを始めてください。」、ログイン画面へのリンク「デモを始め直す」を置く。見た目の比較はこの帯を PC とスマートフォンで撮る。
- ブラウザーのテストはログインした cookie を別の文脈に写し、一方で通常のログアウトを行う。残った文脈は、リセット後と同じくセッションを失い、以前のログインを表す cookie を持つ。
