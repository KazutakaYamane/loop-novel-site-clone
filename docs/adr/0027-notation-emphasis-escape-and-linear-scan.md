# 0027 傍点・`《` のエスケープ・入れ子を一度の線形走査で解釈する

- 状態: 採用
- 日付: 2026-11-27

## 背景

#129 は ADR 0026 のルビの変換に、`《` のエスケープ(AC-F5-9)、傍点(AC-F5-10)、入れ子(AC-F5-12)、サロゲートペアの漢字(AC-F5-15)、閉じない `《`・`《《` を大量に含む行の性能(AC-F5-17)を足す。要件書は、閉じない `《《` の扱いや、`》》》` のように閉じ括弧が続くときにどこで閉じるかを決めていない。カクヨムの採取値([reading-preview.md](../kakuyomu-reference/reading-preview.md))は傍点の見た目だけを記録している。

## 決定

- `parseNotation` は本文を文字列・ルビ `{ base, reading }`・傍点 `{ emphasis }` の並びに分ける。続く文字列は 1 つにつなげる。
- `《` の直前が縦線なら、縦線を出力から外し、`《` を文字として残す。次の文字から走査を続ける。`｜《《傍点》》` の 2 つ目の `《` は直前に漢字がないのでルビにならず、全体が文字になる。
- `《《` は、同じ行で後ろにある最初の `》》` までを傍点の中身にする。中身は解釈せず文字のまま出す。中身が空なら `《《》》` の 4 文字を文字として出す。同じ行に `》》` がなければ、最初の `《` を文字として扱い、次の `《` から走査を続ける。`《《` をルビの読みの始まりにはしない。
- 傍点の始まりの直前の縦線は親文字の指定にならず、文字として残る(縦線は直後の `《…》` にだけ効く。AC-F5-5)。直前の漢字も親文字にならない。
- 閉じ括弧 `》`・`》》` と改行の位置は、前から順に問い合わせる探索器で探す。探索器は前回見つけた位置を、次の問い合わせ位置を超えるまで使い回す。走査位置は前にしか進まないので、閉じない括弧が何個並んでも全体の計算量は本文の長さに比例する。
- 漢字の連続は Unicode のコードポイント単位の正規表現(`u` フラグ)で探すので、`𠮟` などのサロゲートペアも 1 文字の漢字になる。
- `lib/notation/Notation.tsx` が並びを React の要素に組み立てる。傍点は `em` の中に、書記素(`Intl.Segmenter`)ごとの `span` を置き、各 `span` の上中央に 3×3px の点を背景で描く。点の分の上余白は文字の大きさの 0.349 倍にする(PC 17.5px で 6.11px、スマートフォン 16px で 5.58px)。サロゲートペアや異体字セレクタ付きの文字には点を 1 つだけ付ける。傍点の CSS は `lib/notation/Notation.module.css` に置く。
- 話ページの `EpisodeBody` は `Notation` を描画するだけにする。ルビの寸法は ADR 0026 のまま `EpisodeBody.module.css` に置く。

## 結果

- 1 万字の傍点や 10 万個の `《` を含む行も一度の走査で変換でき、単体テストで処理時間の上限を確かめられる。
- 傍点の文字ごとに要素ができるので、傍点が長いほど DOM が増える。本文の上限(10 万字)までは表示できる。
- 閉じ括弧が `》》》` と続くときは最初の `》》` で閉じ、残りの `》` は文字になる。
