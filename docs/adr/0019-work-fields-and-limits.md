# 0019 作品の項目の持ち方と、文字数・タグの上限

- 状態: 採用
- 日付: 2026-11-27

## 背景

#123 で作品のデータと、作成・設定の画面を作る。

- AC-F3-2: タイトル、キャッチコピー、あらすじ(紹介文)、ジャンル(1つ)、タグ(複数)、セルフレイティング(残酷描写・暴力描写・性描写のそれぞれ有無)、連載状態(連載中・完結)を設定・変更できる。
- AC-F3-3: ジャンルの選択肢、各項目の文字数の上限、タグの数の上限はカクヨムに合わせる。カクヨムで確かめられない値は決めて ADR に書く。

カクヨムの作品の設定画面で確かめた値は `docs/kakuyomu-reference/works.md` にある。キャッチコピー 35 文字、タグ 1 つ 20 文字・8 つまで、ジャンル 12 種から 1 つは画面に書かれている。タイトルと紹介文の上限は画面に表示が無く、入力欄にも `maxlength` が無い。保存して確かめることは禁じられている(`docs/kakuyomu-reference.md` の 4 章)。

## 決定

### 上限

| 項目 | 上限 | 根拠 |
|---|---|---|
| タイトル | 100 文字、必須 | カクヨムで確かめられないので決めた。一覧や見出しで扱える長さにし、DB は `VARCHAR(100)` |
| キャッチコピー | 35 文字 | カクヨムの画面 |
| 紹介文 | 10000 文字 | カクヨムで確かめられないので決めた。あらすじと登場人物の紹介に足り、MySQL の `TEXT`(65535 バイト)に UTF-8 で必ず収まる |
| ジャンル | 1 つ。未設定も許す | カクヨムの画面(12 種)。AC-F3-1 は作成のときにタイトルと紹介文だけを求めるので、作った直後は未設定 |
| タグ | 1 つ 20 文字、8 つまで。同じタグは 2 回付けない。空のタグは送らない | カクヨムの画面 |

- 文字数は Laravel の `max`(`mb_strlen`)で数える。前後の空白は Laravel の `TrimStrings` が落とし、空の文字列は `null` になる。
- 上限を超えた入力は画面で止めず(`maxlength` を付けない)、Laravel の確かめで 422 にして項目ごとのエラーの文言を返す。カクヨムと同じく、画面は文字数を表示し、超えたら赤くする。

### 持ち方

- `works` に、所有者(`user_id`)、タイトル、キャッチコピー、紹介文、ジャンル、3 つのセルフレイティング(真偽値の列を 1 つずつ)、連載状態を持つ。
- ジャンルと連載状態は PHP の enum(`App\Enums\Genre`、`App\Enums\SerialStatus`)にし、列にはカクヨムのフォームと同じ値(`fantasy`、`running` など)を入れる。表示名は `Genre::label()` だけが持ち、画面は `GET /api/genres` で選択肢を受け取る。後の issue(シードなど)も同じ enum を使う。
- タグは `tags`(`work_id`、`position`、`name`)に、作品ごとに並び順つきで持つ。作品をまたいでタグの行を共有しない。タグでの検索・一覧は範囲外(要件書 7 章)で、共有すると更新のたびに使われなくなったタグの掃除が要るため。
- 設定の保存(`PUT /api/my/works/{work}`)は、すべての項目を受けて置き換える。タグは作品の行を `lockForUpdate` で固定したトランザクションの中で消して作り直す。同じ作品への保存が重なっても、並びが混ざらず一意の制約で落ちない。

## 結果

- タイトルと紹介文の上限はカクヨムと違う可能性がある。違いが分かったら、この ADR を置き換える。
- タグで作品を探す機能を足すときは、タグの持ち方を見直す。
