# 0020 作品の更新は WorkPolicy で所有者だけに許す

- 状態: 採用
- 日付: 2026-11-27

## 背景

AC-F3-4: 作品を編集できるのはその作品の所有者だけで、他の利用者の編集は拒否される。要件書 6 章は、作品・話の更新を所有者だけに許すことを求める(AC-F4-7 は後の issue)。ログイン状態は Laravel のセッションで持ち(docs/adr/0015)、画面での確かめは表示のためで、データは Laravel が守る(docs/adr/0018)。

## 決定

- 作品の所有者は `works.user_id` で、作成のときにログイン中の利用者を入れる。リクエストの値からは決めない(`user_id` は `Fillable` に入れない)。
- ワークスペースの API は `/api/my/` の下に置き、`auth` ミドルウェアを通す。ゲストは 401。
- 個々の作品を開く・変える経路(`GET`・`PUT /api/my/works/{work}`)は、コントローラーの最初で `Gate::authorize('update', $work)` を呼び、`App\Policies\WorkPolicy::update` が所有者かを確かめる。所有者でなければ 403。無い作品は 404。
- 一覧(`GET /api/my/works`)は、ログイン中の利用者の作品だけを DB から選ぶ。
- 更新の操作は `api` グループの CSRF の検証を通る(docs/adr/0015)。
- 画面(`/my/works/[id]` と `/my/works/[id]/edit`)は、サーバー側で利用者の cookie を付けて同じ API を呼び、403 なら作品の中身を出さずに、編集できない旨を表示する。
- 後の issue で話(エピソード)の更新を足すときも、話の持ち主は作品の持ち主とし、同じ `WorkPolicy` の `update` で確かめる。

## 結果

- 所有者の確かめは `WorkPolicy` の 1 か所にあり、経路を足すときは `Gate::authorize` を呼ぶだけでよい。呼び忘れは、他の利用者で 403 を確かめるテストで見つける。
- 他の利用者が作品の ID を知っていても、中身は返らない(403)。ID が存在するかどうかは 403 と 404 の違いで分かるが、公開済みの作品の ID は作品ページで見えるので隠さない。
