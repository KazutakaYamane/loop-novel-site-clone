# 0028 トップの新着の並びと件数、公開の即時反映

- 状態: 採用
- 日付: 2026-11-27

## 背景

#126 は、話が公開された時刻が新しい順に作品を並べる新着をトップに置き(AC-F7-1、AC-F7-2)、公開済みの話が無い作品をゲストに見せず(AC-F3-5)、公開の直後にゲストが開いた作品ページ・話ページ・新着にその話が出るようにする(AC-F4-4、AC-F4-5)。カクヨムのトップには新着のカードの列が無く、新着は別の一覧(`docs/kakuyomu-reference/new-arrivals.md`)にある。要件書はトップに置くことを求めている。話の `published_at` は秒までの `timestamp` で、列の精度を変えるには既存の列を変えるマイグレーションが要る。

## 決定

- `GET /api/new-arrivals?page=N` は、`Work::published()`(ADR 0024)の作品を、最新話の `published_at` が新しい順に返す。同じ秒に並んだ作品は ID が大きい方を前にする。最新話は公開済みの話を `published_at`、話の ID の順で降順に並べた先頭とし、並び順に使う時刻と表示するタイトルを同じ行から読む。同じ作品の 2 話を同じ 1 秒のうちに公開したときは、公開した順ではなく話の ID が大きい方を最新話として出すことを仕様とする(人間の判断、#126)。人が 1 秒のうちに 2 話を公開することはほぼ無く、公開の順を残すには #124 の公開処理か既存の `published_at` の列を変える必要があるため。AC-F4-4 は、公開ごとに 1 秒以上の間がある通常の操作で満たす。API は作品の ID、タイトル、キャッチコピー、紹介文、作者名、公開済みの最新話のタイトルを返す。カードには作者名の下に最新話のタイトルを出し、作品名から作品ページへ進む。
- 件数とページ送りはカクヨムの新着の一覧に合わせ、1 ページ 30 件にする。Laravel の `simplePaginate` で、次のページの有無(`links.next`)と今のページ(`meta.current_page`)を返す。トップは 1 ページ目を出し、2 ページ目以降は `/new-arrivals?page=N` で同じ部品(`app/_components/NewArrivals/`)が出す。どちらにも「前へ」「次へ」のリンクを置き、1 ページ目へ戻るリンクはトップを指す。ページの値が正の整数でないときは 1 ページ目にする。トップのページは引数を取らない既存の単体テスト(AC-F2-1、AC-F7-3)で描かれるので、検索の値を読む処理はトップに置かない。
- 公開の反映は、新着・作品ページ・話ページのどれもキャッシュせず、リクエストごとに Laravel から読むことで満たす(`fetch` の `cache: "no-store"`)。公開の処理(#124 の `PublishEpisode`)は変えない。性能のためのキャッシュと、公開のときの破棄は #133 で決める。
- 見た目は採取値の一覧の列(幅 825px、カード、見出し枠、次へ)を使う。カクヨムの一覧の左にあるジャンルの選択欄は作らないので(AC-F7-3)、列は中央に置く。作品色のデータは無いので、カード左上の 20×5px の帯は ADR 0025 と同じく本文の文字色で描く。行の高さは採取値(24.57px など)を整数の px に丸める。小数の高さのカードは、上に並ぶカードの数で描画の位置が変わり、要素単位の画像が 1px ずれるため。スマートフォンの「内側の左 56px」は、画面の左端から本文までの距離(カードの外側 16px と内側 40px)と読んだ。
- 見た目の比較は、作品の無いページ(`/new-arrivals?page=9999`)の新着の見出し・空の案内・ページ送りと、デモ作者の初期の作品のカード 1 枚(作者名を `mask` で隠す)を要素単位で撮る。並列のテストとシードで中身が変わる一覧全体は撮らない。

## 結果

- 作品と最新話は同じ SQL 文で読み、作者名はまとめて取得する。件数が増えたときの速さは #133 で測る。
- 同じ秒に公開した作品どうしの前後は、公開の順ではなく作品を作った順で決まる。このため E2E は、作品を作った順と公開した順が同じ 2 つの作品で AC-F7-1 を確かめ、既存の作品の話を公開したときの並びの変化は backend のテストで確かめる。秒より細かく並べるには `published_at` の精度を上げるマイグレーションが要るので、人間の判断を仰ぐ。
- 同じ作品の下書きを、作った順と逆に同じ秒のうちに公開すると、トップのカードには先に公開した(後に作った)話のタイトルが残る。上の判断で、スキーマと公開処理は変えない。
