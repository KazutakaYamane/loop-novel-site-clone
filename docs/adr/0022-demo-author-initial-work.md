# 0022 デモ作者の初期の作品と、デモ作者の移動先

- 状態: 採用
- 日付: 2026-11-27

## 背景

AC-F2-5: デモ作者は、下書きの話と公開済みの話を持つ作品を 1 つ持った状態で始まり、執筆の画面へ移動する。AC-F2-2 はデモ専用の権限・表示・認証の経路を禁じる。デモログインの API の応答と `lib/auth/startDemo.ts` の戻り値は、既存のテスト(人間の承認なしに変えられない)が形を確かめている。

## 決定

- デモ作者の会員登録と同じトランザクションの中で、`App\Actions\Auth\CreateDemoAuthorWork` が作品を 1 つ作る。話は作った順に、公開済みの第 1 話と下書きの第 2 話。公開は作者が画面で公開するときと同じ `PublishEpisode` を通す。文章はこのプロジェクトで書いたもので、カクヨムの作品を使わない。
- 初期の作品は普通の作品・話と同じデータで、デモ作者だけの印や権限を持たない。
- 「執筆の画面」は話の執筆の画面(`/my/works/[id]/episodes/[episodeId]/edit`)とする。ログインが済んだ後、ブラウザが `lib/api/myEpisodes.ts` の `findWritingPath()` で自分の作品の一覧(更新の新しい順)の先頭の作品を読み、その最後の下書きの執筆の画面へ移る。下書きが無ければ作品の画面、作品が無いか読めなければワークスペースへ移る。デモ読者はこれまでどおりトップへ移る。
- 移動先をデモログインの応答に入れない。応答の形と `startDemo` の戻り値を変えずに済み、移動先は利用者の作品という普通のデータだけで決まる。

## 結果

- デモ作者になるたびに公開済みの話を持つ作品が 1 つ増える。E2E と見た目の比較は、他のテストが作った作品の有無に左右されない確かめ方にする(作品を作るテストはデモ読者を使う)。
- ログインの後に一覧を 2 回読むので、デモ作者の移動は 1 往復ぶん遅い。
