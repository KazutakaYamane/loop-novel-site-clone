# 0021 話のデータ、下書きと公開、文字数の上限

- 状態: 採用
- 日付: 2026-11-27

## 背景

#124 で話(エピソード)のデータと、下書きの保存・公開を作る。

- AC-F4-1: 所有者は話のタイトルと本文(プレーンテキスト)を入れ、下書きとして保存できる。AC-F4-2: 下書きは何度でも保存し直せる。
- AC-F4-6: 本文が空の話は公開できず、その旨を表示する。AC-F4-7: 所有者以外は作成・編集・公開できない。AC-F4-8: 話は作った順に並ぶ。
- 要件書 7 章: 予約公開、公開後の編集、非公開に戻す操作、話の並び替え・削除は作らない。
- AC-F5-17 の例(`《` を 10 万個並べた行)を、本文として保存・公開できなければならない(#124 の Notes)。

カクヨムの執筆画面の上限は、ログインした状態で画面を開かないと確かめられない。この ADR を書いた時点では採取できていない(#123 と同じく、人間が用意するログイン状態が要る)。

## 決定

### データ

- `episodes` テーブル: `work_id`、`title`(100 文字)、`body`(MEDIUMTEXT)、`status`(`draft` か `published`)、`published_at`、作成・更新の時刻。
- 作品の中の並びは `id` の昇順(作った順)にする。作成時刻は同じ秒に重なることがあるので、並べる基準にしない。公開や保存し直しでは並びは変わらない。
- 本文はプレーンテキストのまま残す。Laravel の `TrimStrings` は `body` を除く(段落の頭の全角スペースや末尾の空行を消さない)。

### 上限

| 項目 | 上限 | 根拠 |
|---|---|---|
| エピソードタイトル | 必須、100 文字 | 作品のタイトル(docs/adr/0019)にそろえる |
| 本文 | 100,000 文字 | AC-F5-17 の例を保存・公開できる最小の切りのよい値。1 文字 4 バイトでも 400KB で、MEDIUMTEXT(16MB)に収まる |

カクヨムの執筆画面で値が確かめられ、違っていれば、この ADR を置き換える ADR を書く。

### 下書きと公開の API

すべて `/api/my/works/{work}/episodes` の下に置き、`auth` と CSRF の検証を通す。話の所有者は作品の所有者で、`Gate::authorize('update', $work)`(`WorkPolicy`、docs/adr/0020)で確かめる。話は経路の作品に属するものだけを探す(`scoped`)ので、自分の作品の経路から他人の話を指しても 404 になる。

| 経路 | 動き |
|---|---|
| `GET …/episodes` | 一覧(本文を含めない) |
| `POST …/episodes` | 下書きとして作る。本文は空でもよい |
| `GET …/episodes/{episode}` | 1 話を読む |
| `PUT …/episodes/{episode}` | 下書きを保存し直す |
| `POST …/episodes/{episode}/publication` | フォームの内容で保存して公開する。本文が空(空白・改行だけを含む)なら 422 |

- 公開済みの話への保存・公開は 409(公開後の編集は作らない)。利用者の操作で起きる拒否なので HTTP の例外にし、エラーのログに残さない。
- 保存し直しと公開は、話の行を `lockForUpdate` で固定してから状態を確かめる。公開と保存し直しが重なっても公開済みの話は書き換わらず、公開時刻は 1 回だけ決まる。
- 公開の処理は `App\Actions\Episodes\PublishEpisode` の 1 か所にする。後の issue(#126)がトップの新着などへの反映をここにつなぐ。

### 画面

- 作品の画面(`/my/works/[id]`)に話の一覧を作った順に出し、各行から執筆の画面へ移る。一覧は作品とは別に読み、`Suspense` で包む。
- 執筆の画面は新規(`/my/works/[id]/episodes/new`、下書き保存だけ)と既存(`/my/works/[id]/episodes/[episodeId]/edit`、下書き保存と公開)。新規の下書きを保存したら、その話の執筆の画面へ移る。公開したら作品の画面へ移る。
- 公開済みの話の執筆の画面は、フォームを出さずに編集できない旨を出す。

## 結果

- 本文が長くても一覧は軽い(一覧の API は本文を返さない)。
- 公開後の編集・削除を後で作るときは、409 の拒否とこの ADR を置き換える。
