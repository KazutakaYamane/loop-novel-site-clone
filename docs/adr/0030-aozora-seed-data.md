# 0030 青空文庫のシードデータの持ち方と投入

- 状態: 採用
- 日付: 2026-11-27

## 背景

#130 は、青空文庫の著作権が切れた作品をシードとして入れる(AC-F8-1〜AC-F8-6)。

- 作品は複数のジャンルに分けて 10〜20 作品。作者はシードのユーザーとして作る(AC-F8-1)。シードのユーザーでログインする方法は作らない(#130 の範囲外)。
- 青空文庫が表示を求めるクレジット(底本・入力者・校正者など)を作品の中で読めるようにする(AC-F8-2)。
- 青空文庫のルビは F5 の記法として表示し、注記(`［＃…］`)は出さない(AC-F8-3)。
- キャッチコピーとあらすじは作品を読んで新たに書く(AC-F8-4)。
- 投入はネットワークに接続せずに行う。取得は開発時に行い、結果をリポジトリに入れる(AC-F8-5)。
- シードの作品は、トップの新着にその順で並ぶ公開時刻を持つ(AC-F8-6)。新着は ADR 0028 のとおり、最新話の `published_at` の新しい順に 30 件ずつ並ぶ。
- CI の e2e と visual のジョブは `scripts/worktree-setup.sh` で環境を作る。

## 決定

### データ

`backend/database/data/aozora/` に置く。

- `manifest.json`: 人が書くファイル。作品ごとに slug、作者の識別子(`author_key`)、図書カードと zip の URL、ジャンル(`App\Enums\Genre` の値)、タグ、キャッチコピー、あらすじ、最終話の公開時刻(時差つきの ISO 8601)を持つ。
- `source/<slug>.txt`: `php artisan aozora:fetch` が青空文庫の zip から取り出したままのテキスト。Shift_JIS を UTF-8 に、改行を LF にしただけで、変換の入力と、AC-F8-4 の確かめ(写していないこと)に使う。
- `works/<slug>.json`: `php artisan aozora:convert` が `source/` から作る、タイトル・作者・話ごとの本文・クレジット。シードはこのファイルと `manifest.json` だけを読む。

取得はまだ `source/` に無い作品だけを、2 秒ずつ空けて 1 件ずつ行う。図書カードを開かず、索引の CSV で確かめた zip の URL を直接取りに行き、1 作品 1 リクエストにする。作品は作者が没後 70 年を過ぎ、索引の作品・人物の著作権フラグがどちらも「なし」で、翻訳者のいない短い作品から 15 作品を選んだ(11 ジャンル)。

### 変換

- 1 行目をタイトル、最初の空行の前の最後の行を作者にする。「テキスト中に現れる記号について」の囲みを除き、`底本：` で始まる行から後ろをクレジットにする。
- ルビの `《》` と `｜` は、F5 の記法(AC-F5-1〜AC-F5-8)と読み方が同じなので、そのまま残す。15 作品のルビはすべて漢字の親文字か縦線つきで、50 文字を超えるものも無いことを確かめた。
- `［＃「X」に傍点］`(白ゴマ傍点などを含む)は直前の X を、`［＃傍点］…［＃傍点終わり］` は囲んだ文字を F5 の傍点 `《《…》》` にする。直前が X でない(ルビが挟まるなど)ときは注記だけを消す。
- `［＃「X」は大見出し］`・`［＃「X」は中見出し］` の行で話を区切り、X を話のタイトルにする。見出しの前の文章は最初の話の頭に置く。見出しの無い作品はタイトルを話のタイトルにした 1 話にする。
- 外字の注記(`※［＃…］`)は、`U+XXXX` があればその文字に、`第3水準1-87-71` のような JIS X 0213 の面区点があれば EUC-JIS-2004 を通して Unicode の文字にする。二重山括弧の外字は F5 のエスケープ(`｜《`)と `》` にする。どちらも無い外字があれば変換を止め、作品を選び直す。
- そのほかの注記はすべて消し、注記だけの行(字下げ、改ページなど)は行ごと消す。

### 投入

- `Database\Seeders\DatabaseSeeder` が `App\Seed\Aozora\SeedAozoraWorks` を呼ぶ。`scripts/worktree-setup.sh` は `php artisan migrate --seed` を実行するので、開発・E2E・visual・CI の DB には常にシードが入る。手で入れ直すときは `php artisan db:seed --force`。backend のテストはこれまでどおりテスト専用の DB を使い、シードを入れるテストだけが `$this->seed()` を呼ぶ。
- 何度実行しても同じ状態にする。作者は `seed-<author_key>@example.com`(RFC 2606 の予約ドメイン)で、作品は作者とタイトルで探して上書きする。話は作品の中の作った順に上書きし、データより多い話は消す。作品や話の ID は 2 回目以降も変わらない。全体を 1 つのトランザクションで入れる。
- 作者のパスワードは誰にも知らせない乱数にし、2 回目以降は変えない。
- 作品は完結にし、セルフレイティングはすべて無しにする。
- クレジットは、最後の話の本文の末尾に全文を(空行 2 行のあと)置き、作品ページで読めるよう、紹介文の後ろにも「出典：青空文庫（https://www.aozora.gr.jp/）」と底本・入力・校正の行を置く。紹介文は新着のカードにも出るので、全文ではなくこの 3 種の行に絞る。
- 最後の話の `published_at` を `manifest.json` の公開時刻にし、それより前の話は 1 分ずつ前にする。公開時刻は固定の過去の時刻(2026-11-26 の 21 時から 1 時間ずつ前)で、何度入れても同じ並びになる。`timestamp` の列は時差を持たないので、アプリの時間帯に直してから入れる。

### 確かめ方

- AC-F8-6 の E2E は、他のテストが公開した作品がシードより上に並ぶので、新着をページ送りでたどってシードの作品どうしの前後を見る。backend のテストは、シードだけの DB で新着の API の並びが公開時刻の順になることを見る。
- AC-F8-4 は文章を新たに書いたことを求めるので、機械では、キャッチコピーとあらすじが取得したままの本文と 12 文字以上続けて一致しないことを backend のテストで確かめる。
- AC-F8-5 は backend のテストで、外へのリクエストを禁じたまま `db:seed` が通ることを確かめる。

## 結果

- シードの公開時刻は固定の過去の時刻なので、デモの利用者が公開した作品が増えるほど、シードの作品は新着の後ろのページに下がる。毎日のリセット(#131)で利用者の作品が消えると、シードの作品が先頭に戻る。
- 作品を足すときは `manifest.json` を書いて 2 つのコマンドを実行する(README.md の「シードデータ」)。変換の規則で扱えない注記が見つかったら、変換を足すか作品を選び直す。
- `source/` と `works/` で同じ本文を 2 回持つ(データ全体で約 0.8MB)。変換の規則を変えたときに、取得し直さずに変換し直すため。
