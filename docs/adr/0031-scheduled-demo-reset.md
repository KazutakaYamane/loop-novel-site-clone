# 0031 シードの URL を保ってデモデータを毎日消す

- 状態: 採用
- 日付: 2026-11-28

## 背景

#131 で、毎日 4:00 JST と手動コマンドでデモをシードの状態に戻す(AC-F9-1〜AC-F9-3)。Compose の `scheduler` は Laravel の `schedule:work` を実行する。公開ページはリクエストごとに API を読む(ADR 0028)。

## 決定

- `app:reset --isolated=1` を人もスケジューラも呼ぶ。重複起動は Laravel のコマンドロックで防ぐ。毎日の予定は `Asia/Tokyo` を明示して 04:00 にする。
- MySQL のトランザクションで同梱データからシードを上書きし、シードに含まれない作品・ユーザーを消す。話とタグは外部キーのカスケードで消える。シードの作品と話は既存の ID を引き継ぎ、削除した行の ID は再利用しない。古い URL やセッションが別のデータを指さないようにするため。
- 同じ処理でセッション、パスワード再設定の行、ジョブと Laravel キャッシュを消す。デモログインと話の送信のレート制限は同じキャッシュにあり、キーと期限をまとめて消す。Compose の Redis ではキャッシュの DB とコマンドロックの DB が分かれている。
- 新着・作品・話は `no-store` で読み直すので、Next.js の再検証用の API は不要。Laravel の公開 API と Next.js の取得処理のテストでリセット直後の読み取りを確かめる。共有 DB を使うブラウザーのテストからリセットは実行しない。
