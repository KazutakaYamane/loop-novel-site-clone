# 0016 見た目の基準画像は、issue が名指ししたものだけ撮り直してよい

- 状態: 採用(0013 を置き換える)
- 日付: 2026-11-27
- 決めた人: 人間(ハーネスの変更として)

## 背景

0013 は、マージ後の基準画像を既存のテストとして変えられない前提で、後の issue が中身を足す領域を `mask` で隠して撮ることにした。#121 で、この前提が成り立たないことが分かった。#119 の時点でヘッダーの右側の操作の領域(`header-actions`)は空で幅が 0 だったため、`mask` は何も隠していなかった。そこにボタンを置くと、要素の幅だけ `mask` の箱が描かれ、既存の基準画像と必ず食い違う。画面は issue ごとに少しずつ育つので、隠す領域を前もって正しく決め切ることはできない。そのたびに人間の承認待ちになり、issue が一列に依存しているとループ全体が止まる。

基準画像は、判定の処理ではなく期待する出力である。テストの処理(`*.visual.spec.ts`)と違い、画像を差し替えても判定が甘くなるわけではない。

## 決定

- PR が閉じる issue の "Likely files" に、`__screenshots__/` の中のパス(ファイル名、またはその中の glob)で名指しされた基準画像は、その PR で更新・削除してよい。`e2e/visual/**` のような広い指定では名指しにならない。
- CI の guard は、PR の本文の `Closes #<n>` から issue を読み、その "Likely files" と照らして判定する。名指しされていない既存の基準画像の変更は、今までどおり落とす。
- 名指しは計画役と分け直し役が行う。実装とレビューの役は issue の本文を書き換えられない(hook が止める)。名指しが足りなければ `replan` で戻す。
- 要素単位で撮ること、実行ごとに中身が変わる領域を `mask` で隠すことは続ける。後の issue が中身を足す領域を前もって隠す必要はなくなる。

## 結果

- 画面に中身を足す issue は、人間の承認なしで基準画像を撮り直せる。
- issue が名指しした基準画像の中で起きた意図しない崩れは、CI では見つけられない。名指ししていない画面の崩れは、今までどおり見つけられる。PR に CI の差分画像を添えるので、後から確かめることはできる。
- 実装の iteration が自分の issue を書き換えて名指しを足すことは、hook が `gh issue edit` の本文の変更を止めるだけで、シェルの抜け道は残る。
