# 0023 話の作成・編集の送信回数の制限

- 状態: 採用
- 日付: 2026-11-27

## 背景

AC-F4-9 は、話の作成・編集の送信回数を利用者単位で制限することを求める(#134)。要件書は上限の値と期間を決めていない。

- 話の送信は 3 つの経路にある(docs/adr/0021): 作成(`POST …/episodes`)、下書きの保存し直し(`PUT …/episodes/{episode}`)、公開(`POST …/episodes/{episode}/publication`)。公開もフォームの内容を保存するので、編集の送信である。
- 既存の E2E(#124 の下書き保存・再保存・公開など)は、1 人の利用者が 1 つのテストで数回送る。テストの環境だけで上限を変える分岐は作らない(AGENTS.md「Forbidden shortcuts」)。
- デモログインの制限(docs/adr/0017)は、Laravel のレートリミッター(`AppServiceProvider` と `config/rate-limits.php`)で IP ごとに数える。#134 の Notes により、それらのファイルは変えない。
- カクヨムの執筆画面の送信の上限は公開されておらず、確かめられない。

## 決定

### 上限

- 利用者ごとに、**10 分間 30 回**まで。3 つの経路の送信を合わせて数える。31 回目からは 429 と `Retry-After` を返し、話を作らず、変えず、公開しない。
- 根拠: 人が手で「下書き保存」を押す速さでは、10 分に 30 回(20 秒に 1 回)はまず届かない。一方、スクリプトで連投すると数秒で止まり、本文の上限(10 万字、docs/adr/0021)と掛け合わせても 10 分で書き込めるのは高々 300 万字ほどに収まる。期間を 10 分と短くするのは、上限に当たった人が長く待たずに済むようにするためである。
- 既存の E2E は 1 人の利用者が数回しか送らないので、この値で変わらずに通る。
- 値は環境変数で変えない。テストの環境でも本番と同じ値で働く。

### 仕組み

- デモログインと同じく Laravel のレートリミッター(`RateLimiter::for` と `throttle` ミドルウェア)を使う。キャッシュのストア(compose では Redis)にカウンタを持つ。
- リミッター `episode-submission` は `App\Providers\EpisodeRateLimitServiceProvider` に定義し、`bootstrap/providers.php` に登録する。値はこのクラスの定数に置く(デモログインの `config/rate-limits.php` に足さない)。
- キーはログイン中の利用者の ID(`Auth::id()`)。送信元の IP は使わないので、同じ IP の別の利用者の送信は数えない。
- `routes/api.php` で、3 つの経路だけに `throttle:episode-submission` を付ける。読む経路(一覧・1 話)は数えない。
- ミドルウェアは `api` グループ(セッションと CSRF の検証)と `auth` の後に通る。そのため、ゲスト(401)と、CSRF のトークンが無い・偽物の送信(419)は数えない。他人の作品への送信(403)は、送った利用者の回数として数え、作品の持ち主の回数には入らない。

### 画面

- 執筆の画面のフォームは、429 を受けたら、ボタンの下に「エピソードを保存できる回数の上限に達しました。10分ほどおいてからもう一度お試しください。」を `role="alert"` で出す(`app/my/_components/EpisodeRateLimitNotice/`)。次の送信が上限以外の理由で返ったら消す。
- カクヨムに相当する画面は確かめられないので、文言は自分で書き、色はデモログインの案内と同じく既存の CSS 変数(`--color-error`)を使う。

### テスト

- E2E(`@AC-F4-9`)と見た目の比較は、そのテストのデモ作者が本物の上限まで画面から送る。制限は利用者ごとなので、並列に動く他のテストに影響せず、`page.route` で 429 を作らなくてよい。
- 上限と期間の境界、拒まれる場合(ゲスト、他の利用者、CSRF)は backend のテストで確かめる。

## 結果

- 1 人の利用者は 10 分に 30 回までしか話を作成・編集できない。手で書く人が当たることはほぼ無い。
- カウンタはキャッシュにあるので、キャッシュを消すと数え直しになる(手元の `scripts/e2e.sh` の `cache:clear` もこれを消す)。
- 上限の値を変えるときは、この ADR を置き換える ADR を書く。
